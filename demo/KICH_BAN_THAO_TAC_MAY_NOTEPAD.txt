CHUẨN BỊ
1. Mở DBeaver/pgAdmin trên nhánh Neon demo riêng; Terminal tại gốc repository.
2. Kiểm tra endpoint và cấu hình .env; không hiển thị mật khẩu khi trình chiếu.
3. Chạy khối nhận diện môi trường trước. Phiên bản server phải đọc từ kết quả thật.
4. Khởi tạo: mở sql/netcafe_cloud_init.sql và chạy trên database demo được phép tái tạo.
   File này xóa và tạo lại tám schema trong transaction. Không dùng cho dữ liệu cần giữ.
5. Nếu giữ database hiện có: xem backup và sql/14_defense_demo_fixes.sql trước khi cập nhật.
   Bản bàn giao chưa áp dụng migration này lên Neon; kiểm tra quyền trước khi demo ghi.
6. ETL có ghi/xóa dữ liệu demo. Kết quả 20 đầu vào = 16 nạp + 4 loại là mốc đã thử,
   khi trình chiếu phải đọc lại số liệu của lần chạy.
7. Demo 3 chính: mở demo/demo_6_index_fixture.sql, chạy trên cùng một kết nối.
   Bảng tạm 20.000 dòng, EXPLAIN trước/sau B-Tree, cuối file ROLLBACK.
   Không ép planner; đọc kế hoạch và thời gian thật, không hứa mức tăng tốc cố định.
8. Demo cảnh báo: mở listener Python trước, chờ đăng ký kênh rồi chạy giao dịch nạp tiền.
   Giao dịch này COMMIT và tăng số dư trên database demo. Đối chiếu alert_id và thời gian.
9. Chạy từng khối SQL trong cùng phiên; khi cố tình gây lỗi, chạy riêng ROLLBACK sau đó.
10. Các phần Admin/Station và backup là mở rộng, chỉ dùng sau khi đã tập đúng môi trường.

GIỚI HẠN CẦN NÓI ĐÚNG
RLS của thu ngân theo employee mapping, không tự động giới hạn theo ca sáng.
Các module AI hiện dùng quy tắc, so khớp và thống kê; có thể trả về tập rỗng hợp lệ.
Gateway ntfy là HTTP push, không phải SMS nhà mạng; không có trong chuỗi demo chính.
Không tự chạy fn_apply_promotions hay gửi thông báo ra điện thoại từ file này.

SQL

SELECT n.nspname AS schema_name,
       count(*) FILTER (
           WHERE c.relkind IN ('r','p') AND NOT c.relispartition
             AND c.relname <> 'qa_reset_marker'
       ) AS logical_tables,
       count(*) FILTER (
           WHERE c.relkind IN ('r','p') AND c.relispartition
       ) AS partition_tables,
       count(*) FILTER (WHERE c.relkind = 'v') AS views,
       count(*) FILTER (WHERE c.relkind = 'm') AS materialized_views
FROM pg_namespace n
LEFT JOIN pg_class c ON c.relnamespace = n.oid
WHERE n.nspname IN (
    'core','inventory','billing','hr',
    'audit','ai','reporting','staging'
)
GROUP BY n.nspname
ORDER BY n.nspname;

Phần mở rộng Trình diễn luồng Admin và Station
SQL

SELECT c.computer_code, s.session_id, s.status,
       s.last_heartbeat_at, s.close_reason,
       i.invoice_id, i.total_amount,
       p.method, p.amount
FROM core.gaming_session s
JOIN core.computer c ON c.computer_id = s.computer_id
LEFT JOIN billing.invoice i ON i.session_id = s.session_id
LEFT JOIN billing.payment p ON p.invoice_id = i.invoice_id
ORDER BY s.session_id DESC
LIMIT 5;

SELECT count(*) AS invalid_customers
FROM core.customer
WHERE full_name <> btrim(full_name)
   OR phone !~ '^0[35789][0-9]{8}$'
   OR balance < 0;

SELECT count(*) AS wrong_invoice_formula
FROM billing.invoice
WHERE total_amount <>
      play_amount + service_amount + surcharge - discount_amount;

SELECT status, count(*) AS session_count,
       max(start_time) AS latest_start
FROM core.gaming_session
GROUP BY status;

SELECT c.computer_code, c.status,
       s.session_id, s.last_heartbeat_at
FROM core.computer c
LEFT JOIN core.gaming_session s
  ON s.computer_id = c.computer_id AND s.status = 'active'
ORDER BY c.computer_code;
